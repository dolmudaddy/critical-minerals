# 희토류 지식 위키 — 운영 규칙 (Schema)

이 vault는 **Seong-Jun Cho의 핵심광물 큐레이션 + 개인 희토류 나무위키** 통합 저장소다.
Karpathy의 "LLM Wiki" 아이디어를 기반으로 한다: 주간 수집 기사가 vault에 자동으로 쌓이면, Claude가 읽고 정제해서 교차참조된 위키 페이지(`wiki/`)로 만들고, 사용자는 필요할 때 질문한다.

> ⚠️ **공개 저장소 주의**: 이 vault는 공개 GitHub 저장소(`dolmudaddy/critical-minerals`)의 일부이며 obsidian-git이 주기적으로 자동 커밋·푸시한다. **`wiki/`는 `.gitignore`로 제외된 개인 영역**이다. Claude는 (1) `.gitignore`에서 `vault/wiki/` 항목을 제거하지 않고, (2) 위키 내용·미션 분석을 `wiki/` 밖의 추적되는 폴더로 옮기거나 복사하지 않는다.

## 0. 사용자 미션 (모든 작업의 기준점)

> 한국이 **희토류를 자체 확보**하기 위한 **탐사 → 채굴 → 선광 → 분리정제 → 정책** 전(全) 밸류체인을 개발한다.

위키의 모든 정제·요약·판단은 이 미션 관점에서 이루어진다. "이 자료가 내 미션에 어떤 의미가 있는가?"가 항상 첫 질문이다. 미션의 정식 정의는 [[내-미션-방향성]]에 있다.

## 1. 폴더 구조

```
vault/                     ← Claude Code 실행 위치 (이 파일이 있는 곳)
├─ CLAUDE.md               ← 이 파일. 운영 규칙
├─ articles/               ← CMW 주간 기사 md (GitHub Actions 자동 생성, 읽기 전용)
├─ KCMO/articles/2026/     ← KCMO 주간 기사 md (자동 생성, 읽기 전용)
└─ wiki/                   ← 정제된 지식. Claude가 작성·관리 (git 제외, 개인 영역)
   ├─ index.md             ← 전체 목차 (카테고리별 분류)
   ├─ log.md               ← 작업 이력
   ├─ *.md                 ← 개별 위키 페이지 (플랫, 하위폴더 없음)
   └─ raw/                 ← 구(舊) 위키 시스템의 원본 아카이브 (읽기 전용)
      ├─ cmw_*.json, kcmo_*.json  ← 과거 주간 수집 JSON (기존 출처 인용용)
      └─ paper/            ← 사용자가 수집한 학술논문 PDF
```

- **기사 원본 = vault의 md 노트**: `articles/`(CMW)와 `KCMO/articles/`(KCMO)는 매주 월요일 08:00 KST GitHub Actions가 생성하고, obsidian-git이 시작 시 자동 pull로 받아온다. Claude는 이 폴더들을 **절대 수정·삭제하지 않는다** (원본이자 사이트 소스).
- `wiki/`의 페이지는 하위 폴더 없이 플랫하게 관리한다 (`raw/`는 아카이브 예외).
- 분류는 폴더가 아니라 `wiki/index.md`의 카테고리로 한다.
- 이 vault는 **Obsidian**으로 열린다 → `[[위키링크]]`, `> [!callout]` 문법이 네이티브로 렌더링된다. 기사 노트와 위키 페이지가 같은 vault에 있으므로 **위키 페이지에서 기사 노트로 직접 `[[링크]]`할 수 있다.**

## 2. 위키 페이지 작성 규칙 (가장 중요)

### 2.1 모든 페이지는 Takeaway 콜아웃으로 시작한다
페이지 맨 앞(제목 바로 아래)에 반드시 `> [!takeaway]` 콜아웃 블록을 넣는다.
여기에는 **"내 미션·방향성 관점에서 이 내용의 핵심 takeaway"**를 쓴다.
단순 요약이 아니라 **"그래서 내가 뭘 가져가야 하는가"**를 적는다. 사용자가 첫 문단만 읽어도 핵심을 잡을 수 있어야 한다.

```markdown
# 페이지 제목

> [!takeaway] 🎯 내 관점 핵심
> - (미션 관점에서 가장 중요한 시사점 1~3개)
> - 예: "중국의 수출통제 품목 확대는 우리 분리정제 자립 일정을 앞당겨야 할 신호."
> - 관련: [[연결-페이지]]

## 개요
(구체적 내용 시작...)
```

### 2.2 교차참조를 적극적으로 한다
- 다른 페이지에서 언급되는 모든 개념·기업·국가·기술·정책은 `[[위키링크]]`로 연결한다.
- 아직 없는 페이지라도 일단 `[[새-개념]]`으로 링크를 건다(미작성 표시 역할).
- 페이지 하단에 `## 관련 문서` 섹션을 두고 핵심 연결을 모은다.
- **출처 표기**:
  - 새로 정제하는 기사: vault 내 기사 노트를 `[[파일명]]` 위키링크 또는 경로(`KCMO/articles/2026/....md`)로 인용한다.
  - 논문: `wiki/raw/paper/파일명.pdf`. DOI나 저널 URL이 확인되면 함께 보존한다.
  - 기존 페이지의 `raw/...` 인용은 구 시스템 유산이며 현재 위치는 `wiki/raw/...`이다. 마주칠 때마다 고칠 필요는 없고, 해당 페이지를 갱신하는 김에 바로잡는다.
- **원문 URL이 있으면 함께 보존한다.** 기사 frontmatter에 `url`/source_url이 있으면 [[원문-링크]] 인덱스에 추가한다. 단, Google 뉴스 링크(`news.google.com/rss/...`)는 **브라우저 클릭으로는 원문 이동되지만 서버에서 자동 본문수집은 불가**하다 — 본문이 꼭 필요하면 제목으로 WebSearch하여 실제 언론사 페이지를 찾아 보강한다.

### 2.3 페이지 표준 구조
```markdown
# 제목

> [!takeaway] 🎯 내 관점 핵심
> ...

## 개요
## (본문 섹션들)
## 내 미션 관점 시사점     ← takeaway를 더 자세히 풀어쓰는 곳
## 출처
## 관련 문서               ← [[링크]] 모음
```

### 2.4 페이지 메타데이터
모든 페이지 최상단에 YAML frontmatter를 둔다:
```yaml
---
category: 경쟁환경 | 기술 | 정책 | 프로젝트 | 개념
country: 중국 | 미국 | 한국 | ...
created: 2026-06-20
updated: 2026-06-20
sources: [KCMO/articles/2026/파일명.md]
---
```

### 2.5 파일명 규칙
- 한글 케밥/공백 무방, 검색 가능하게 명확히. 예: `중국-희토류-수출통제.md`, `선광-부유선별.md`.
- 페이지는 **개념 단위**로 쪼갠다. 한 자료에 여러 주제가 섞여 있으면 여러 페이지로 분리하고 서로 링크한다.

### 2.6 언어 정책
- **모든 위키 페이지는 한국어로 작성한다.** 원본 자료가 영어·중국어·일본어 등 어떤 언어로 들어와도 정제된 위키 페이지 본문은 한국어로 쓴다.
- 고유명사(기업명·기관명·기술용어)는 한국어 + 괄호 원문 병기를 원칙으로 한다. 예: `희토류 분리 (rare earth separation)`, `중국희토집단 (China Rare Earth Group)`.
- 원문 인용이 꼭 필요하면 인용 블록으로 원어를 남기되, 해설·요약은 한국어로 한다.

## 3. 세 가지 운영 방법

### 🟢 운영 1. 자료 넣기 (Ingest)
**트리거**: 사용자가 **"이번 주 정리해줘"**라고 말하거나, 특정 자료를 가리키며 "정리해줘" / "위키에 추가해줘" / "이거 읽어봐"라고 말한다.

**"이번 주 정리해줘"의 새 자료 찾는 법** (구 시스템의 `_pending.md`는 폐지됨):
1. `wiki/log.md`에서 마지막 Ingest 날짜를 확인한다.
2. `articles/`와 `KCMO/articles/2026/`에서 파일명 날짜가 그 이후인 기사 md를 모은다. (git이 있으므로 `git log --diff-filter=A` 로 최근 추가 파일을 찾아도 된다)
3. 같은 기사가 해시 접미사만 다른 중복 파일로 여러 개 존재할 수 있다(예: `...-c171.md`, `...-f2df.md`). 내용을 비교해 **스토리 단위로 묶어 한 번만** 정제한다.

**Claude의 작업 순서**:
1. 해당 기사 노트를 읽는다. (`articles/`·`KCMO/`는 절대 수정·삭제하지 않는다)
2. 미션 관점에서 핵심을 추출한다. **희토류·미션 관련성**을 먼저 판정하고, 무관한 광종(우라늄·니켈 단독 등)은 제외하되 제외 사실을 log에 남긴다. 보더라인이면 🟢/🔴 판정 근거를 적는다.
3. 자료를 **개념 단위**로 나눠 `wiki/`에 페이지를 생성/갱신한다.
   - 기존 페이지에 해당하면 **갱신**하고 `updated` 날짜를 바꾼다.
   - 새 주제면 새 페이지를 만든다.
4. 각 페이지에 **Takeaway 콜아웃**(§2.1)을 반드시 넣는다.
5. **교차참조**(§2.2)를 건다. 관련된 기존 페이지에도 역링크를 추가하고, 정제에 쓴 기사 노트로도 `[[링크]]`를 건다.
6. `wiki/index.md`를 갱신한다 (카테고리에 새 페이지 등록).
7. `wiki/log.md`에 작업 1줄을 기록한다.
8. 사용자에게 **무엇을 만들었고/바꿨는지 + 미션 관점 핵심 takeaway**를 요약 보고한다.

**논문(wiki/raw/paper/) 처리 시 추가 규칙**:
- 관련성 판정은 위와 동일. 논문은 주로 ⚗️기술·📖개념 카테고리로 정제하며, 허브 페이지 [[희토류-연구개발-방향]]에 연결한다.

### 🔵 운영 2. 질문하기 (Query)
**트리거**: 사용자가 위키에 대해 질문한다 ("중국 수출통제 현황 어때?", "우리 선광 옵션 정리해줘").

**Claude의 작업 순서**:
1. 먼저 `wiki/`에서 답을 찾는다 (index.md → 관련 페이지). 필요하면 기사 원본(`articles/`·`KCMO/`)과 `wiki/raw/`도 참조.
2. 미션 관점에서 답한다. 단순 나열이 아니라 **"그래서 내 방향성에 뭘 의미하는가"**를 포함한다.
3. 근거 페이지를 `[[링크]]`로 인용한다.
4. 위키에 정보가 없으면 "위키에 없음"을 명시하고, 자료를 넣어달라고 안내한다 (추측으로 채우지 않는다). 사용자가 원하면 WebSearch로 on-demand 조사 후 신규 페이지를 만들 수 있다(출처 URL 명시).
5. 질문 과정에서 위키의 빈틈/오류를 발견하면 사용자에게 알린다.

### 🟡 운영 3. 건강검진 (Health Check)
**트리거**: 사용자가 "건강검진" / "위키 점검해줘" / "정리 상태 봐줘"라고 말한다.

**Claude가 점검·보고하는 항목**:
1. **고아 페이지**: 아무 페이지에서도 링크되지 않은 페이지.
2. **깨진 링크**: `[[링크]]` 했지만 실제 파일이 없는 미작성 페이지 → 채울 가치 있는지 제안.
3. **index 누락**: `wiki/`에 있지만 `index.md`에 없는 페이지.
4. **Takeaway 누락/형식 위반**: §2.1 콜아웃이 없거나 단순 요약에 그친 페이지.
5. **중복/충돌**: 같은 주제가 흩어져 있거나 내용이 상충하는 페이지 → 병합/정리 제안.
6. **오래된 정보(stale)**: 시의성 있는 주제(가격, 정책, 경쟁사 동향)인데 오래 갱신 안 된 페이지.
7. **미정제 기사**: 마지막 Ingest 이후 들어온 기사 중 아직 위키에 반영 안 된 것.
8. **git 안전**: `.gitignore`에 `vault/wiki/`가 살아 있는지, `git status`에 wiki 파일이 추적 대상으로 뜨지 않는지 확인.

보고는 **문제 목록 + 수정 제안**으로 하고, 사용자 승인 후 일괄 정리한다. log.md에 기록한다.

## 4. 카테고리 (index.md 분류 기준)

| 카테고리 | 내용 |
|---|---|
| 🌍 경쟁환경 | 중국·미국·인도·일본 등 국가별 동향, 경쟁사 분석, 시장·가격 |
| ⚗️ 기술 | 탐사 / 채굴 / 선광 / 분리정제 공정·기술 |
| 📜 정책 | 한국 및 각국 희토류 정책, 규제, 수출통제, 보조금 |
| 🏗️ 프로젝트 | 사용자의 희토류 프로젝트 기록 |
| 📖 개념 | 광종·용어·기초 지식 (밸류체인 공통 참조용) |

새 주제가 어디에도 안 맞으면 카테고리를 추가하고 이 표도 갱신한다.

## 5. 불변 규칙 (반드시 지킨다)
- ❌ 기사 원본(`articles/`·`KCMO/`)과 아카이브(`wiki/raw/`)를 수정·삭제·이동하지 않는다. **읽기 전용**이다.
- ❌ `.gitignore`의 `vault/wiki/` 제외를 해제하지 않고, 위키·미션 내용을 git 추적 폴더로 옮기지 않는다 (공개 저장소).
- ✅ 위키 페이지는 **항상 Takeaway 콜아웃으로 시작**한다 (§2.1).
- ✅ 위키 페이지 본문은 **항상 한국어로 작성**한다. 원본 언어와 무관하다 (§2.6).
- ✅ **교차참조를 항상 적극적으로** 건다 (§2.2).
- ✅ 자료를 넣을 때마다 **index.md와 log.md를 갱신**한다.
- ✅ 모든 정제·판단은 **미션 관점**([[내-미션-방향성]])에서 한다.
- ✅ 위키에 없는 사실을 추측으로 지어내지 않는다. 근거는 기사 노트·논문·명시된 웹 출처에 둔다.

## 6. 자료 유입 경로 (구 "주간 자동 수집" 대체)

구 시스템(D:\2026\wiki_cho\wiki_test)의 `tools/weekly-ingest.ps1` + Windows 작업 스케줄러 방식은 **2026-09-14 폐지**되었다. 이제 자료는 다음 경로로 자동 유입된다:

1. **GitHub Actions** (`.github/workflows/weekly.yml`): 매주 일요일 23:00 UTC(월요일 08:00 KST)에 기사를 수집·요약하여 저장소의 `vault/articles/`·`vault/KCMO/`에 md로 커밋.
2. **obsidian-git**: Obsidian 시작 시 자동 pull(`autoPullOnBoot`)로 새 기사를 받아온다. 오래 안 열었으면 수동으로 `Obsidian Git: Pull` 명령 실행.
3. 위키 정제는 수동 트리거: 사용자가 **"이번 주 정리해줘"**라고 말할 때 §3 운영 1을 수행한다.

논문 등 수동 자료는 사용자가 `wiki/raw/paper/`에 넣고 "정리해줘"라고 요청한다.
